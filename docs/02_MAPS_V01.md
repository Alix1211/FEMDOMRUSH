# 02. 초기 게임판 3종 — FEMDOM RUSH v0.1

좌표는 화면 기준 **정규화 좌표(0~100)**다. 실제 해상도와 무관하게 비율로 배치한다.

공통 규칙:
- 적 이동은 미리 정의된 waypoint 배열을 따라간다.
- 배치 슬롯은 맵 이미지에 박지 않고 데이터로 관리한다.
- 슬롯은 평소 숨기고, 유닛 선택 시 반투명/점선 타원으로 표시한다.
- `type=melee`는 길 가장자리 또는 길 위와 겹치는 저지 슬롯.
- `type=ranged`는 길 바깥 원거리 슬롯.
- `type=hybrid`는 둘 다 가능.
- 시작 3개 맵은 시스템 검증용으로, 서로 다른 전략을 강제한다.

# MAP 01 — 붉은 초원 관문

## 목적
튜토리얼 + 기본 상성 학습.

- 입구: 1
- 출구: 1
- 배치 슬롯: 9
- 웨이브: 5
- 목표 플레이 시간: 90~120초
- 핵심 학습: 배치, 방향, 저지, 궁수/마법 상성, 업그레이드, 조기 웨이브

## 테마
ARPG 봄/여름 필드 자산 재사용.

권장 자산:
- `assets/field_props/spring/*`
- `assets/field_props/summer/*`
- grass/dirt edge
- 바위, 꽃, 나무, 표지판

## 경로
왼쪽에서 들어와 S자로 휘어 오른쪽 하단 출구로 이동.

```json
{
  "path": [
    [0,35],[12,35],[22,28],[35,28],[45,40],
    [54,52],[66,52],[76,44],[88,44],[100,62]
  ]
}
```

## 배치 슬롯
```json
[
  {"id":"M1","x":21,"y":40,"type":"melee","radius":7},
  {"id":"R1","x":18,"y":20,"type":"ranged","radius":18},
  {"id":"R2","x":34,"y":18,"type":"ranged","radius":18},
  {"id":"M2","x":47,"y":47,"type":"melee","radius":7},
  {"id":"R3","x":47,"y":27,"type":"ranged","radius":18},
  {"id":"R4","x":60,"y":66,"type":"ranged","radius":18},
  {"id":"M3","x":71,"y":49,"type":"melee","radius":7},
  {"id":"R5","x":78,"y":28,"type":"ranged","radius":18},
  {"id":"R6","x":88,"y":58,"type":"ranged","radius":18}
]
```

## 웨이브 초안
1. 슬라임 × 10
2. 고블린 × 12
3. 슬라임 × 8 + 고블린 × 8
4. 오크 × 6 + 고블린 × 10
5. 오우거 × 1 + 오크 × 8

## 설계 포인트
- M2가 첫 핵심 병목.
- R3와 R4는 같은 병목을 양쪽에서 지원.
- 오크부터 DEF를 주어 궁수만 도배하면 효율이 떨어지도록 한다.
- 5웨이브에서 오우거를 저지하는 동안 마법/고화력 유닛을 쓰게 한다.

- 궁수 또는 대공 특화 유닛의 존재 이유를 확실하게 보여준다.
- 샤먼은 후방 회복. 기본 타겟팅은 출구 우선이므로 자연스럽게 까다롭게 느껴지게 한다.

- 입구: 2
- 출구: 1
- 배치 슬롯: 14
- 웨이브: 9
- 보스: 1
- 목표 플레이 시간: 150~210초
- 핵심 학습: CC, 밀치기, 특화 분기, SP 타이밍, 조기 웨이브 리스크

## 테마
ARPG 폐허/동굴 자산 재사용.

- `assets/dungeon/tiles/*`
- `assets/dungeon/props/*`

## 보스
**오우거 지휘관** 또는 ARPG의 대형 몬스터 중 하나.

초기 규칙:
- Block 요구 3
- 밀치기 면역
- 일정 간격으로 아군 근접 유닛 넉백
- HP 50% 이하에서 이동속도 +20%
- 처치 직전 대량 잡몹 1회 소환

## 설계 포인트
- PUSH 슬롯에 밀치기 유닛을 배치하면 구덩이를 이용할 수 있다.
- C_M1은 강력하지만 보스 넉백 때문에 완전한 영구 봉쇄는 불가능.
- 후반에는 물리/마법/공중/회복 적을 섞어 원툴 전략을 막는다.
- 조기 호출을 잘 쓰면 마지막 웨이브 직전 SP를 당겨 보스전에 활용 가능.

# 맵 제작 공통 데이터 형식

```json
{
  "id": "stage_001",
  "theme": "spring",
  "lives": 20,
  "initialDP": 12,
  "initialGold": 150,
  "paths": [
    {"id":"A","waypoints":[[0,35],[20,35],[100,60]]}
  ],
  "deploySlots": [
    {"id":"M1","x":20,"y":40,"type":"melee","radius":7}
  ],
  "hazards": [],
  "waves": []
}
```

맵 그래픽과 전투 규칙을 분리한다. 같은 배경을 재사용해도 path/slot/wave 데이터만 바꾸면 별도 스테이지로 운용할 수 있다.

# 100스테이지 확장 원칙

새 배경 100장이 필요하지 않다.

- 베이스 맵 12~15개
- 경로 A/B 사용 여부 변경
- 슬롯 일부 잠금
- 입구 순서 변경
- 웨이브 조합 변경
- 공중/회복/정예 비율 변경
- 특수 지형 활성/비활성
- 보스 추가

이 조합으로 100스테이지를 만든다. 핵심은 **맵 그림의 수가 아니라 웨이브와 슬롯 조건의 변화**다.
